# Coordination: one system for every contributor

Status: adopted 27 Nov 2026 (owner, ledger B23). Applies to the owner, Claude, Codex/GPT and Google AI Studio alike. Where another document disagrees about *who works on what and how work is tracked*, this file wins.

## 1. Why

Work was lost or duplicated because each AI worked from its own chat: AI Studio pushed a rewrite straight to `main`, plans were rewritten from the newest chat only, and asks made in one tool never reached the others. The fix is that **GitHub is the only shared memory**. A chat is never the record; if it is not in the repo or an issue, it does not exist.

## 2. The four records

| Record | Where | What it holds | Who writes it |
|---|---|---|---|
| **Ledger** | `docs/LEDGER.json` (rendered to `docs/LEDGER.md`) | Every ask the owner ever made and every feature promised, with status. Rows are never deleted. | Any agent, through a PR (`tools/ledger.py --add`) |
| **Plan** | `docs/ROADMAP.md` (features → mechanics → tickets), `docs/MASTER_PLAN.md`, `docs/DESIGN.md`, `docs/EXECUTION_STRATEGY.md` | Order of work, rules, targets | Claude (planner), owner approves |
| **Tickets** | GitHub issues labelled `ticket` | One unit of work: ledger row, goal, files, acceptance checks, priority | Any agent; usually Claude |
| **Board** | Issue #1 "Start here", body regenerated by `coord.yml` | Ready, claimed, in review and blocked tickets; ledger rows with no ticket; new asks waiting for intake | The workflow only (do not edit the body by hand) |

Every open ledger row must have a ticket (or a stated reason it waits). Every ticket names its ledger row in a line `Ledger: A5` (several: `Ledger: A1, B5`). `tools/coord.py audit` checks both directions every night and on every board refresh; gaps are listed at the top of the board until someone fixes them.

## 3. The life of a request

1. **The owner asks for something in any tool** (Claude chat, Codex, AI Studio).
2. **Intake, before any code.** The AI that hears the ask records it the same day, in one of two ways:
   - It can use GitHub: open an issue with the **Owner request** form (label `owner-ask`), quoting the owner's words. Or add the ledger row and ticket directly in its PR.
   - It cannot use GitHub issues (AI Studio): it writes a file `docs/inbox/<yyyy-mm-dd>-<slug>.md` with the owner's words, on its own branch, and opens or asks the owner to open a PR.
3. **Triage (planner, at least once a day).** Each `owner-ask` issue or inbox file becomes a ledger row plus one or more tickets with acceptance checks and a priority. The `owner-ask` issue is closed with links; the inbox file is deleted in the same PR. Nothing is dropped: an ask the owner later cancels becomes a `closed` ledger row with the owner's note.
4. **Claim.** An agent picks the **first unclaimed ticket in Ready** that it can do (priority `p1` before `p2` before `p3`, then lowest number), and comments on the ticket:
   `/claim <agent> <branch>` (for example `/claim codex t/a5-oil-wells`). The workflow labels it `claimed` and `agent:<agent>` and the board shows it. One active claim per ticket; the earliest comment wins.
5. **Work** on branch `t/<id>-<slug>` from `main`, never on `main`. Push often: a branch push is the sign of life.
6. **Pull request** with `Closes #<ticket>` and `Ledger: <id>` in the body. CI's `coord` job fails a PR without them, from a branch not named `t/...`, or that removes or weakens a ledger row.
7. **Review.** Another agent (by default Claude) audits the PR; the owner merges. The board shows it under In review.
8. **Done.** Merging closes the ticket. The PR sets the ledger row to `done` with date and probe, or leaves it `partial` and names the follow-up ticket.

Release a claim you cannot finish: `/release <what is done, what is left>`. A ticket can be marked `/blocked <reason>`; `/unblock` returns it to Ready. A claim with no branch push for 3 days is shown as **stale** on the board; anyone may then ask for a handoff on the ticket, and the owner can `/release` it.

## 4. Rules that stop solo streaks

1. **Nothing reaches `main` except a reviewed PR.** Branch protection on `main`: require a pull request and the `quick` and `coord` checks, and do **not** allow administrators to bypass (AI Studio pushes with the owner's account, so a bypass lets it through). Owner action, see §7.
2. **No code without a claimed ticket.** A PR whose `Closes #` points at an issue that is not labelled `ticket` fails `coord`. Small fixes found on the way get their own ticket first (one minute) or go in the same ticket only if they touch the same files.
3. **One ticket, one branch, one agent.** Two agents may work at once only on tickets whose files do not overlap; the ticket's "Files" field says which files it touches.
4. **Engine changes keep the game identical unless the ticket says otherwise.** The PR states the seed-7 state hash before and after and why it changed; CI compares with `tools/check_century.py`.
5. **Plans change only through a PR to the plan files**, never by a chat alone. A plan PR keeps every open ledger row mapped to a ticket.
6. **Session end:** comment on your ticket what is done, what is left, last commit, tests run. The next agent starts from that comment, not from a chat.

## 5. Session start (every agent, every time)

1. Read the board (issue #1).
2. `python3 tools/ledger.py --open` (or read `docs/LEDGER.md`).
3. Do intake for any ask the owner gave you in this session (§3 step 2).
4. Resume your own claimed ticket if you have one; otherwise claim the first Ready ticket you can do.

## 6. Agents and how each one connects

| Agent | Reads at start | Writes | Notes |
|---|---|---|---|
| Claude | `CLAUDE.md`, board | issues, branches, PRs, reviews; planner and triage | Scheduled review runs `tools/coord.py audit` and triages the inbox |
| Codex/GPT | `AGENTS.md`, board | issues, branches, PRs | Same claim commands |
| Google AI Studio | `docs/AI_STUDIO.md` (paste into its system instructions) | its own branch only; asks go in `docs/inbox/` | If its GitHub sync can only push to `main`, branch protection refuses it; then download the zip and give it to Claude or Codex, who open the PR |
| Owner | the board | decisions, merges, `owner-ask` issues | Can type `/release`, `/blocked`, set priority labels |

## 7. Owner settings (one time)

1. Settings → Branches → rule for `main`: require a pull request before merging; require status checks `quick` and `coord`; tick "Do not allow bypassing the above settings" and remove any bypass list (otherwise AI Studio, which pushes as the owner, gets through).
2. Settings → Actions → General → Workflow permissions: read and write (the board workflow edits issue #1 and labels).
3. In AI Studio: paste `docs/AI_STUDIO.md` into the app's system instructions.

## 8. Tools

- `tools/coord.py board [--write]`: render the board from issues, PRs and the ledger (`--write` updates issue #1).
- `tools/coord.py audit`: ledger rows without a ticket, tickets without a ledger row, inbox files, stale claims. Exit code 1 if any gap.
- `tools/coord.py pr-check`: the PR rules in §3 step 6 (used by CI).
- `.github/workflows/coord.yml`: runs the claim commands, refreshes the board on every issue, comment and PR event and nightly, and runs `pr-check` on pull requests.
