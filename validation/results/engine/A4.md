## 1. MODEL_REV and the load path (src/ui.js)
- `saveJSON` writes `modelRev: MODEL_REV` next to `saveSchema` (the codec, still 3). `unpack` reads and removes both, so neither lives in G (a saved fresh game restores byte for byte). A save without `modelRev` (older than A4) reports revision `null` = unknown, never a guess. A save from a newer revision is refused. `LAST_LOAD = {savedRev, modelRev, defaults}` reports what a load did.
- `applySaveDefaults(g)` runs once in `unpack`, is idempotent, and creates no key that a fresh game lacks:

| Added by | Field | Behaviour on load |
|---|---|---|
| A1 | G.commandSerial, G.actorSerial | invalid values dropped (engine reads absent as 0); absent stays absent |
| A2 | project `pid`, G.projectSeq | every live project without a (unique) pid gets `p<n>` in province-list order; the sequence continues above every id in the save. Same save -> same ids (tested). Legacy projects get `paidUnknown:1` when `paid` was never recorded |
| A2 | queue order id | missing or duplicate ids get `legacy-<index>`, unique per nation |
| A2 | endProject dispositions | `recoverable` 0 always; a legacy project's `spent` is `null` (unknown) with `paidSinceLoad`; legacy completed-works and ledger rows of canceled projects get recoverable 0 and null for spent/unspent that were never recorded. No code path credits any treasury |
| A2 | constructionSequence | continues above every ledger id |
| A3 | localMarket, landUse, employerAccount | not read before the month's pass rewrites them; absent is valid; no default written |
| A3 | G.unif, G.ev markers, "dec" cards | read with a guard; a pending card is plain data and still resolves |
- Fixtures loaded (real path, fresh vm per load): prev_build_save.txt (t=30, no saveSchema), seed7_1840 (t=48), seed7_1866 (t=360), seed7_1934 (t=1176); plus a fresh GBR save at month 10 with 52 live projects (one part-funded), 4 queued orders. Pids assigned: 89, 73, 23, 50 (and 0 for the fresh save).
- test_a4.js (164+ checks, 30 s): unique ids and identical ids on every load; save, restore, save, restore gives byte-identical text; restored twice then 12 months equals the never-resaved run (digest); saved after 6 months and resumed in a fresh engine equals the uninterrupted run; every project and queue order live at the load is still live, completed once, or has an end record (none lost, none ended twice, none both ended and live); every disposition has recoverable 0; a legacy project canceled by transfer: one record, spent null, no treasury gained money; no NaN or Infinity in G.
